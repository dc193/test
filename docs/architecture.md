# AI 公司系统架构设计

## 概述

本系统是一个多层级的 AI 智能体架构，模拟一个自我进化的"AI 公司"。系统能够接收任务、咨询专业视角、做出决策、执行任务，并通过元认知层持续自我优化。

---

## 三层架构

```
┌─────────────────────────────────────────────────────┐
│                   上帝层 (God Layer)                 │
│                    Meta-cognition                   │
│                                                     │
│  职责：观察系统运行，发现模式，触发进化                │
│  触发：每周定时 + 事件驱动（每 N 个任务后）            │
│  权限：有限自动执行，有安全边界                       │
└─────────────────────────────────────────────────────┘
                          │
                          │ 观察 / 进化指令
                          ▼
┌─────────────────────────────────────────────────────┐
│                   CEO 层 (CEO Layer)                 │
│                  Decision & Execution               │
│                                                     │
│  职责：接收任务 → 理解意图 → 咨询顾问 → 决策 → 执行    │
│  能力：调用工具、访问知识库、协调顾问团               │
└─────────────────────────────────────────────────────┘
                          │
                          │ 咨询（非指派）
                          ▼
┌─────────────────────────────────────────────────────┐
│                 顾问团 (Advisory Layer)              │
│                  Thinking Frameworks                │
│                                                     │
│  职责：提供专业视角和建议，不参与执行                  │
│  形态：思维框架（非固定人设）                         │
│  基础视角：战略、产品、技术、用户、商业...             │
└─────────────────────────────────────────────────────┘
```

---

## 各层详细设计

### 1. 上帝层 (God Layer)

**定位**：系统的元认知层，负责观察和进化，不参与具体任务执行。

#### 触发机制
| 类型 | 条件 | 说明 |
|-----|------|-----|
| 定时触发 | 每周一次 | 全面分析系统运行状况 |
| 事件触发 | 每完成 N 个任务 | 快速检查，发现即时问题 |

#### 权限范围

**可以自动执行：**
- 分析任务完成情况，生成统计报告
- 发现知识缺口，记录学习建议
- 有限度自动学习（每周最多 N 条新知识）
- 整理和优化知识库标签

**需要确认/不能做：**
- 删除已有知识
- 修改核心系统配置
- 超出学习配额的操作

#### 核心能力
```python
class GodLayer:
    # 观察
    def observe_task_patterns(self) -> TaskAnalysis
    def identify_knowledge_gaps(self) -> list[KnowledgeGap]

    # 进化
    def suggest_learning(self) -> list[LearningSuggestion]
    def auto_learn(self, max_items: int) -> list[Knowledge]

    # 报告
    def generate_weekly_report(self) -> EvolutionReport
```

### 2. CEO 层 (CEO Layer)

**定位**：系统的核心执行层，负责理解任务、做出决策、调度执行。

#### 工作流程
```
用户任务
    │
    ▼
┌─────────────┐
│  理解意图    │  分析任务类型、目标、约束
└─────────────┘
    │
    ▼
┌─────────────┐
│  咨询顾问    │  根据任务性质，选择相关视角咨询
└─────────────┘
    │
    ▼
┌─────────────┐
│  综合决策    │  整合各方建议，形成执行方案
└─────────────┘
    │
    ▼
┌─────────────┐
│  执行任务    │  调用工具、生成输出
└─────────────┘
    │
    ▼
┌─────────────┐
│  记录反馈    │  供上帝层分析
└─────────────┘
```

#### 核心能力
```python
class CEOAgent:
    # 任务处理
    async def handle_task(self, task: Task) -> TaskResult

    # 顾问咨询
    async def consult_advisors(self, context: str) -> list[AdvisorOpinion]

    # 知识检索
    async def search_knowledge(self, query: str) -> list[Knowledge]

    # 工具调用
    async def execute_action(self, action: Action) -> ActionResult
```

### 3. 顾问团 (Advisory Layer)

**定位**：知识的"人格化接口"，提供多元视角，不参与执行。

#### 设计原则
- **思维框架，非固定人设**：顾问代表的是思考方式，不是具体的"人"
- **按需咨询**：CEO 根据任务性质决定咨询哪些视角
- **只提供建议**：顾问不执行任务，只输出观点和建议

#### 基础视角
| 视角 | 关注点 | 典型问题 |
|-----|-------|---------|
| 战略视角 | 长期方向、竞争格局、资源配置 | "这对长期有什么影响？" |
| 产品视角 | 用户需求、功能优先级、体验 | "用户真正需要什么？" |
| 技术视角 | 可行性、架构、性能、安全 | "技术上怎么实现最优？" |
| 用户视角 | 行为动机、心理、体验感受 | "用户会怎么想/怎么做？" |
| 商业视角 | 成本、收益、商业模式 | "这能赚钱吗？怎么赚？" |
| 风险视角 | 潜在问题、法规、安全 | "有什么风险？" |

#### 核心接口
```python
class AdvisorySystem:
    # 获取建议
    async def get_perspective(
        self,
        perspective: str,  # "strategic", "product", "technical"...
        context: str
    ) -> AdvisorOpinion

    # CEO 发起咨询
    async def consult(
        self,
        task_context: str,
        perspectives: list[str] = None  # None = 自动选择
    ) -> list[AdvisorOpinion]
```

## 数据流

### 任务处理流程
```
用户 ──任务──▶ CEO层
                │
                ├──咨询──▶ 顾问团 ──建议──┐
                │                        │
                ├──检索──▶ 知识库 ──知识──┤
                │                        │
                ◀────────综合决策─────────┘
                │
                ├──执行──▶ 工具/动作
                │
                └──记录──▶ 任务日志 ──▶ 上帝层观察
```

### 进化流程
```
上帝层
   │
   ├──观察──▶ 任务日志
   │            │
   │            ▼
   │         模式分析
   │            │
   │            ▼
   ├──发现──▶ 知识缺口
   │            │
   │            ▼
   ├──学习──▶ 新知识 ──▶ 知识库
   │
   └──报告──▶ 进化周报 ──▶ 用户
```

## 安全边界

### 上帝层限制
| 限制项 | 值 | 说明 |
|-------|---|-----|
| 每周自动学习上限 | 10 条 | 防止 token 消耗失控 |
| 单次学习冷却 | 1 小时 | 避免频繁触发 |
| 知识删除 | 禁止 | 只能标记过时，不能删除 |
| 配置修改 | 禁止 | 核心配置需人工修改 |

### CEO 层限制
| 限制项 | 值 | 说明 |
|-------|---|-----|
| 单任务最大 token | 可配置 | 防止单任务消耗过大 |
| 工具调用白名单 | 可配置 | 限制可调用的工具范围 |

## 配置示例

```yaml
# config/system.yaml

god_layer:
  # 触发配置
  schedule:
    weekly_day: "sunday"
    weekly_hour: 3  # 凌晨3点
  event_trigger:
    task_count: 20  # 每20个任务触发一次

  # 限制配置
  limits:
    max_weekly_learning: 10
    learning_cooldown_hours: 1

ceo_layer:
  # 默认咨询的视角（可被任务覆盖）
  default_perspectives:
    - strategic
    - product
    - technical

advisory:
  # 可用视角
  available_perspectives:
    - strategic
    - product
    - technical
    - user
    - business
    - risk
```
