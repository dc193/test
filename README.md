# 研究员招聘管理系统

## 项目概述

一个基于 AI 的招聘管理系统，用于研究员岗位的招聘流程管理。系统通过 Notion 作为数据展示层，结合自建后端的 AI Agent 进行智能评估。

### 核心目标

1. **提升面试效率** - AI 自动生成评估报告和面试问题
2. **统一数据视角** - 打破原有 Project 数据孤岛，宏观管理所有候选人
3. **流程标准化** - 5 轮面试流程清晰可追踪
4. **个性化评估** - 每位面试官可配置自己的评估 Prompt

---

## 招聘流程

```
简历筛选 → 一面 → 作业评估 → 二面 → 三面 → 试用期 → 老板面试 → 正式录用
    ↓        ↓        ↓         ↓      ↓       ↓         ↓
  淘汰     淘汰     淘汰      淘汰   淘汰    淘汰      淘汰
```

### 各阶段详情

| 阶段 | 输入 | AI 处理 | 输出 |
|------|------|---------|------|
| 简历筛选 | 简历 PDF + 作品 PDF | 评估候选人匹配度 | 评分 + 建议面试问题 |
| 一面 | 面试录音转录文本 | 分析面试表现 | 评估报告 |
| 作业评估 | 候选人提交的股票分析作业 | 评估作业质量 | 评审意见 |
| 二面 | 面试录音转录文本 + 历史记录 | 分析面试表现 | 评估报告 |
| 三面 | 面试录音转录文本 + 历史记录 | 分析面试表现 | 评估报告 |
| 试用期 | 试用期表现记录 | 综合评估 | 是否推荐老板面 |
| 老板面试 | 全部历史记录 | 汇总报告 | 最终建议 |

## Notion 数据库结构

### Database 1: 候选人 (Candidates)

| 字段 | 类型 | 说明 |
|------|------|------|
| 姓名 | Title | 候选人姓名 |
| 状态 | Select | 简历筛选/一面/作业/二面/三面/试用期/老板面/录用/淘汰 |
| 联系方式 | Text | 电话/邮箱 |
| 简历 | Files | PDF 文件 |
| 作品 | Files | PDF 文件 |
| AI简历评估 | Text | 系统自动生成 |
| 建议面试问题 | Text | 系统自动生成 |
| 创建时间 | Date | 自动记录 |
| 淘汰原因 | Text | 可选填写 |

### Database 2: 面试记录 (Interviews)

| 字段 | 类型 | 说明 |
|------|------|------|
| 候选人 | Relation | 关联候选人表 |
| 轮次 | Select | 一面/二面/三面/老板面 |
| 面试官 | Select | 负责该轮的面试官 |
| 转录文本 | Files | 上传的面试录音转录文本 |
| AI评估结果 | Text | 系统自动生成 |
| 面试官评价 | Text | 面试官手动填写 |
| 结果 | Select | 通过/淘汰/待定 |
| 面试时间 | Date | 面试日期 |

### Database 3: 作业记录 (Assignments)

| 字段 | 类型 | 说明 |
|------|------|------|
| 候选人 | Relation | 关联候选人表 |
| 作业内容 | Files | 候选人提交的股票分析作业 |
| AI评估 | Text | 系统自动生成 |
| 评审人 | Select | 下一轮面试官 |
| 评审意见 | Text | 评审人手动填写 |
| 结果 | Select | 通过/淘汰 |

### Database 4: 面试官配置 (Interviewers)

| 字段 | 类型 | 说明 |
|------|------|------|
| 姓名 | Title | 面试官姓名 |
| 负责轮次 | Select | 一面/二面/三面/老板面 |

| 参考文件 | Files | 补充评估材料 |

## AI Agent 架构

### Master Agent

负责：
- 解析请求类型（简历评估/面试分析/作业评审等）
- 从 Notion 拉取必要的历史数据
- 构建精简上下文，控制 Token 消耗
- 路由到对应的 SubAgent
- 将结果写回 Notion

### SubAgents

| Agent | 输入 | 输出 |
|-------|------|------|
| 简历评估 Agent | JD + 简历 + 作品 | 匹配度评分 + 建议面试问题 |
| 面试分析 Agent | 历史摘要 + 转录全文 + 面试官Prompt | 结构化评估报告 |
| 作业评审 Agent | 作业内容 + 评审标准 | 作业评价 |
| 数据洞察 Agent | 统计数据 | 招聘漏斗分析、面试官效能分析 |

### Token 优化策略

1. **分层摘要**：每轮面试结束后生成 300 字结构化摘要，后续轮次只传摘要，必要时才加载全文
2. **按需加载**：默认传递精简信息，用户请求时才加载完整内容
3. **Prompt 模板化**：使用固定格式减少重复 Token
4. **PDF 智能提取**：只提取关键段落，不传输完整 PDF 文本

### 上下文传递规则

| 阶段 | 传递的上下文 |
|------|-------------|
| 简历评估 | JD + 简历全文 + 作品全文 |
| 一面分析 | 简历摘要 + 转录全文 + 面试官Prompt |
| 二面分析 | 简历摘要 + 一面摘要 + 一面评价 + 转录全文 + 面试官Prompt |
| 三面分析 | 简历摘要 + 一面摘要 + 二面摘要 + 历史评价 + 转录全文 + 面试官Prompt |
| 老板面 | 全流程摘要汇总 + 转录全文 |
